# PLAN-GATE

Рішення щодо готовності плану до реалізації для інформаційної системи Cinema Booking System (версія 1.0.0).

Дата фіксації: 2026-11-01  
Рішення: **GO з умовами**  
Ухвалив: автор проєкту (vlb103)  
Артефакти: `docs/plan/decomposition.md`, `docs/plan/plan.md`, `docs/plan/gantt.md`, `docs/plan/risks.md`, матриця простежуваності (Додаток А в `spec/srs.md`)

## Перевірка критеріїв

1. **Декомпозиція покриває SRS.** Усі 36 вимог мають тікети, тікетів без вимоги немає. Покриття показано в матриці простежуваності.
2. **Залежності логічні.** 123 залежності без циклів, кожен тікет веде до Gate релізу T-79, кожна Feature має Test. Залежності внесено в GitHub як зв'язки «Blocked by».
3. **Ризики мають заходи.** Для кожного з 11 ризиків визначено захід і пріоритет, для 7 груп вимог з високою ціною помилки визначено додатковий контроль і Gate.
4. **План узгоджений.** Етапи, тривалості, критичний шлях і оцінка людських дій наведено в `plan.md` і `gantt.md`.

## Чек-лист для кожного Gate

- [ ] Геш `spec/srs.md` не змінився без рішення автора.
- [ ] Кількість тестів не зменшилась порівняно з попереднім прогоном.
- [ ] Людина сама запустила повний комплект тестів і звірила результат зі звітом агента.
- [ ] Для кожного нового тесту є протокол Red і Green.
- [ ] Припущення агента, яких немає в SRS, погоджено автором.
- [ ] Рішення записано з переліком перевірених пунктів і зауважень.

## Наслідки рішення

`plan.md` і `gantt.md` відображають план на момент PLAN-GATE. Через нову залежність стрес-тест T-71 виконується разом з ядром бронювання (E3), а не в E9. Етапи й критичний шлях буде оновлено під час наступної ітерації планування.

Реалізацію дозволено, починаючи з Gate T-02. Агент не ухвалює Gate і не закриває Gate-тікети.
